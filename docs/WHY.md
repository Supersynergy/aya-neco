# Why AYA-NECO Exists

AYA-NECO exists to make a difficult idea testable:

Can a person contribute something useful, receive a transparent demo reward, attach impact evidence, and export a verifiable proof without starting with banks, token sales, or heavy infrastructure?

## The Problem

Common-good work and environmental work often disappear into stories, PDFs, spreadsheets, or unverifiable claims.

That creates four problems:

1. Contributors do not see a clear value loop.
2. Communities cannot inspect how balances were created.
3. Environmental impact claims are hard to audit.
4. Builders jump too early into token narratives before proof exists.

## The Bet

Start smaller.

Build a local proof lab where every value update is derived from explicit events:

- who contributed;
- what was claimed;
- which rule was applied;
- what proof was created;
- which trust level the event has;
- how the receipt can be exported.

## Why Local First

Local-first removes friction:

- no wallet setup required;
- no RPC endpoint required;
- no production identity required;
- no token required;
- no external validator required.

Then the same shape can be lifted into real infrastructure:

- DID/OIDC/eIDAS for identity;
- MRV validators for environmental claims;
- IOTA for notarization;
- ONCE/WODA for module portability.

## What Success Looks Like

The first success is not a production currency.

The first success is a working demonstration that a non-technical person can understand and a technical person can fork:

1. Create or use demo identity.
2. Submit contribution.
3. Apply Gradido-style or Planedo-style rules.
4. Produce event hash.
5. Export receipt.
6. Wrap receipt for ONCE/WODA or send proof hash to IOTA.
